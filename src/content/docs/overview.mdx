Attest 1.1.0 "Hardened" tests AI agents with pytest and Vitest. It checks what an agent says, which tools and agents it calls, and what it changes in an external system. Record model responses once and replay them against your real code to test changes without live model calls for matching requests.

## One small test

Install with `uv add "attest-ai>=1.1.0" pytest`, save this as `test_support.py` and run `uv run pytest`:

```python
from attest import agent, expect


@agent("support")
def support(builder):
    builder.add_tool_call("lookup_order", args={"order_id": "O-1"}, result={"status": "delivered"})
    return {"message": "Order O-1 was delivered."}


def test_checks_the_reply_and_tool(attest):
    attest.evaluate(expect(support()).required_tools(["lookup_order"]).output_contains("O-1"))
```

This records sample data and makes no network calls. For your application, record real execution with an adapter or capture, then choose checks for your business rules. A recording consistent with its own trace is not proof that the behavior is correct.

## Record, replay, gate

1. **Capture** a run and review its redacted data and drafted contracts.
2. **Replay** recorded model responses while the current agent code runs. Strict replay reports a mismatch instead of inventing a response; isolate tools and time-dependent state too.
3. **Gate** the result with policies and reviewed baselines. Failed native tests block by default; `not_evaluated` only warns unless you configure `not_evaluated: block`. Require the policy check in branch protection.

The [tour](/tour/) shows this workflow on a synthetic double refund. The [1.1 release post](/blog/v110-release/) explains evaluated-chain enforcement, relational effects, scheme-2 assertion ids, baseline removals and judge failure handling.

## Checks and providers

Free deterministic checks run before embedding and judge checks. Embedding and judge cost depends on the selected provider: OpenAI embeddings and hosted judges may cost money; local ONNX embeddings or a local judge endpoint avoid those provider API charges. ACP judges are local-only and unsandboxed; read the safety guidance before using one. Plugins define their own cost and determinism.

## Install and runtime

```bash
# Python
uv add "attest-ai>=1.1.0" pytest
uv run attest doctor

# TypeScript
npm install -D "@attest-ai/core@>=1.1.0" "@attest-ai/vitest@>=1.1.0" "vitest@^4"
npx attest doctor
npx vitest run
```

For TypeScript, run `npx attest doctor` before the first test: downloading the engine on a cold machine can exceed Vitest's default timeout. The Vitest integration supports versions 3, 4 and 5; see the release notes for concurrent lifecycle limitations.

The SDK starts a Go engine subprocess and communicates over JSON-RPC/NDJSON. Published SDK packages download the matching engine version and verify its pinned hash. Source/editable installs require a local engine build and `ATTEST_ENGINE_PATH`. Optional local ONNX embeddings also need ONNX Runtime. See [configuration](/sdk-guides/configuration/) for details.
